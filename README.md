# ESP32-Climate-Camera — v1.2.0

Контроллер климатической камеры на классическом двухъядерном ESP32 (WROOM-32 / ESP32 Dev Module), с **ST7789 240×240**, SHT30/31, энкодером, управлением вентилятора, Wi-Fi, встроенным веб-интерфейсом и Web OTA.

Это заново собранный **архив исходников v1.2.0**, не переименованный архив предыдущей версии. Климатический модуль основан на предоставленном исходнике предыдущего релиза, сетевой модуль интегрирован в этом пакете. Файлы старых прошивок `.bin` намеренно отсутствуют. Полная сборка для ESP32 и стендовая проверка не выполнялись; точный отчёт — `BUILD_REPORT.md`. Не считать этот пакет испытанной промышленной прошивкой.

## Содержание

- `ClimateCamera_1_2_0_IDE1819/` — скетч и все исходники.
- `TFT_eSPI_setup/User_Setup.h` — активный профиль библиотеки TFT_eSPI.
- `docs/OTA.md`, `docs/API.md` — обновление и программный доступ.
- `CHANGELOG.md`, `RELEASE_NOTES.md`, `VERSION` — версия и изменения.

- `SHA256SUMS.txt`, `release_manifest.json` — контроль содержимого.

## Аппаратные подключения

| Узел | Вывод ESP32 / настройка |
|---|---|
| ST7789 MOSI / SCLK | GPIO 23 / GPIO 18 |
| ST7789 DC / RST | GPIO 25 / GPIO 13 |
| ST7789 CS | -1: отсутствие управляемого CS; аппаратный CS при наличии — GND |
| ST7789 размер / SPI | 240×240 / 20 МГц |
| SHT30/31 SDA / SCL | GPIO 21 / GPIO 22; адрес 0x44 |
| IN1: питание вентилятора | GPIO 15 |
| IN2: увлажнитель | GPIO 17 |
| IN3: не используется | GPIO 14; постоянно LOW |
| IN4: холодильник | GPIO 26 |
| Вентилятор PWM / TACH | GPIO 16 / GPIO 27; 25 кГц, 2 импульса на оборот |
| Энкодер A / B / SW | GPIO 32 / GPIO 33 / GPIO 4 |

В этой исходной аппаратной конфигурации реле **активны HIGH**, выключены LOW. Для активных LOW-модулей требуется осознанная адаптация кода и схемы ДО подключения нагрузок. Программные уровни не гарантируют отключение во время сброса ESP32: используйте внешние цепи, обеспечивающие выключенное состояние при старте. GPIO15 и GPIO4 — загрузочные выводы, учитывайте подтяжки платы. Нагрузки питаются отдельно; общая земля необходима для низковольтной части. Не подавайте 5 В на GPIO. Для 4-pin вентилятора применяйте подходящий интерфейс PWM/тахометра, не подключайте неизвестную 5-вольтовую подтяжку к ESP32 напрямую. Коммутация сетевого компрессора требует контактора/реле с подходящим пусковым током и электрических защит.

## Логика работы

- Компрессор: 5 мин после подачи питания и после выключения; минимальный рабочий цикл 2 мин; максимум 40 мин, затем пауза минимум 5 мин. Авария, команда выключения и OTA прекращают работу сразу, несмотря на минимальное время включения.
- Увлажнитель: 20 с включения / 120 с паузы при сохраняющемся запросе влажности.
- IN3 исключён из регулирования и постоянно выключен.
- SHT30: совместное измерение температуры/влажности, проверка CRC8, тайм-аут I²C и восстановление шины. При недействительных/устаревших данных выходы отключаются.
- Вентилятор: исходный ПИ-регулятор и инверсный PWM; аппаратные параметры сохранены.
- Настройки сохраняются в NVS по явной команде; совместимый формат предыдущего исходника сохранён.
- **Автозапуск включён после каждого сброса/включения питания**, в том числе после успешного OTA. Данные датчика и защитная задержка компрессора остаются обязательными. Выключение через Web UI не сохраняется как запрет следующего автозапуска.
- Периодический двухминутный сброс ST7789 отключён. Передаются изменившиеся полосы изображения. Тайм-аут очереди полос не является доказательством аппаратной диагностики SPI; зависание внутри блокирующего вызова обслуживается общей стратегией WDT, а не достоверно распознаётся TFT-драйвером.
- Task WDT: целевое время 8 с для основного цикла.

## Сборка в Arduino IDE

Целевая среда: **Arduino IDE 1.8.19 / 2.x**, пакет **ESP32 by Espressif Systems 2.0.17**, плата **ESP32 Dev Module**. Исходники содержат ветки для изменений WDT/PWM в core 3.x, но эта комбинация здесь не проверена. Для предсказуемой первой сборки используйте 2.0.17.

1. Распакуйте архив. Не меняйте имя папки скетча отделно от имени `.ino`.
2. Установите библиотеку **TFT_eSPI** через менеджер библиотек. `Wire`, `Preferences`, `WiFi`, `WebServer`, `Update`, `ESPmDNS` входят в Arduino-ESP32. Внешние AsyncWebServer, ArduinoJson и отдельная библиотека SHT30 не нужны.
3. Сделайте резервную копию `Arduino/libraries/TFT_eSPI/User_Setup.h`, затем замените его файлом `TFT_eSPI_setup/User_Setup.h` из архива. В `User_Setup_Select.h` библиотеки должен быть выбран именно этот `User_Setup.h`, а не другой профиль. Копия в папке скетча сама по себе конфигурацию библиотеки **не переключает**.
4. В папке скетча скопируйте `Secrets.example.h` в `Secrets.h`. Укажите домашний SSID/пароль при необходимости, смените пароль AP и пароль администратора. `Secrets.h` исключён из Git. В архив не включён личный пароль домашней сети из переписки.
5. Откройте `ClimateCamera_1_2_0_IDE1819/ClimateCamera_1_2_0_IDE1819.ino`.
6. Выберите ESP32 Dev Module, Flash Size **4MB**, Partition Scheme **Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)**. Не используйте Huge APP / No OTA. Скорость USB начните с 115200; 921600 используйте только при стабильном соединении.
7. Нажмите «Проверить». Если драйвер дисплея или GPIO выбраны неверно, компиляция остановится на диагностике `#error`.
8. Первую прошивку с нужной таблицей разделов выполните **по USB**. Проверьте Serial Monitor 115200 и все выходы без подключённых силовых нагрузок.

Перед подключением компрессора проверьте на стенде полярность реле, PWM, тахометр, отказ датчика, уставки, временные защиты и отключение на время OTA. Программные защиты не заменяют независимую аппаратную защиту оборудования.

## Сеть и веб-интерфейс

Работает AP+STA: резервная точка **всегда включена**, параллельно с попытками подключения к домашнему роутеру. При пустом `CC_WIFI_SSID` используются только AP и локальный сервер.

Заводские значения в примере (обязательно сменить перед эксплуатацией): AP `ClimateCamera-AP`, пароль `Climate120!`; HTTP пользователь `admin`, пароль `Climate120!`. По AP откройте **http://192.168.4.1/**. В домашней сети используйте IP из Serial Monitor или **http://climate-camera.local/**, если устройство поддерживает mDNS. Интернет для интерфейса не нужен.

Веб-интерфейс показывает температуру, влажность, реле, RPM и защитную паузу; позволяет менять уставки, параметры вентилятора, калибровку, Kp/Ki, включать/выключать систему и подтверждать аварию. Страницы и скрипты встроены в прошивку, внешних CDN нет. Пока энкодер находится в режиме локального редактирования, удалённые изменения отклоняются.

HTTP реализован штатным **синхронным WebServer в отдельной задаче Core 0**, а не ESPAsyncWebServer. Климат и TFT обслуживает Arduino loop на Core 1 при стандартной конфигурации классического ESP32. Обмен: очередь команд, подтверждение результата и защищённый снимок телеметрии. Сетевая задача не меняет GPIO, NVS или климатическую конфигурацию напрямую.

Все веб-маршруты защищены HTTP Basic Auth; изменяющие запросы дополнительно требуют токен `X-Climate-Token`, получаемый из `/api/status`. Это не TLS и не криптографическая подпись прошивки. **Не открывайте сервер в Интернет, не делайте проброс порта**; используйте доверенную локальную сеть. Домашний пароль не возвращается API.

## Обновление OTA

Откройте **http://192.168.4.1/update** или `/update` по IP домашней сети. Загрузите только `.bin` приложения, полученный командой «Скетч → Экспорт бинарного файла» для этой платы и схемы разделов. Старые `.full.bin`, bootloader, partitions и merged-образы не подходят.

Перед первым байтом записи сетевой модуль получает подтверждение отключения выходов от климатического ядра. Без подтверждения запись не начинается. После успешной валидации образа отправляется ответ и выполняется перезагрузка. При ошибке/отмене текущая работа остаётся остановленной; автоматического перезапуска по ошибке нет, нужно проверить состояние и включить вручную. Не отключайте питание при записи. Подробности — `docs/OTA.md`.
