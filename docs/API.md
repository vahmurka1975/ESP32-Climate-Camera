# REST API — v1.2.0

Все маршруты требуют HTTP Basic Auth. Данные логина задаются в Secrets.h. Сначала выполните GET `/api/status` и прочитайте поле `token`. Для POST передавайте его заголовком `X-Climate-Token`. Токен обновляется при перезагрузке. CORS не включён. Сервер принимает формы `application/x-www-form-urlencoded`, а не JSON-тела.

## GET /api/status

Возвращает версию, `temp`/`hum`, `rpm`, `pwm`, `enabled`, `sensorOk`, `pwmReady`, `fanTachFault`, `fridge`, `humid`, `fan`, `otaMode`, `uiEditing`, `fridgeWait`, `fridgeWaitSec`, `fridgeRunSec`, `uptimeSec`, `sensorAgeSec`, `wifiConnected`, `staIP`, `apIP`, `token` и вложенный `config`. При недействительном датчике температура/влажность — null. Время передаётся в секундах. `pwm` — исходная шкала управляющей величины 0..255, не процент. Пароли никогда не возвращаются.

## GET /api/config

Возвращает текущий снимок Config. `enabled` отражает рабочее состояние, но не сохраняется как запрет автозапуска после перезагрузки.

## POST /api/config

Допускается передать подмножество полей. Неизвестные поля и нечисловые/выходящие за границы значения отклоняются. Дополнительно `save=1` сохраняет конфигурацию в NVS; `save=0` или отсутствие save применяет только в RAM.

| Поле | Диапазон |
|---|---|
| tempTarget | 2..30 °C |
| tempHyst | 0.2..5 °C |
| humTarget | 30..98 % |
| humHyst | 1..10 % |
| fanWorkMin | целое 1..180 мин |
| fanPauseMin | целое 0..360 мин |
| fanTargetRPM | целое 300..1500 RPM |
| tempOffset | -5..5 °C |
| humOffset | -15..15 % |
| pidKp, pidKi | 0..1 |

Пример тела: `tempTarget=12&humTarget=80&fanTargetRPM=500&save=1`.

## POST /api/control

Тело формы — только `action=on`, `off`, `ack` или `save`. `on` не обходит защиты. Для ack система должна быть выключена; подтверждение аварии не запускает оборудование. Во время OTA разрешено только выключение; остальные изменения блокируются. Локальное редактирование энкодером также блокирует изменения через браузер.

## POST /update

Multipart/form-data с одним файлом `update`, заголовком X-Climate-Token и HTTP Basic Auth. Перед записью нужен подтверждённый безопасный режим. Используйте страницу `/update`, которая сама устанавливает заголовок.

## Ответы

Изменяющие запросы возвращают `{"ok":true|false,"message":"..."}`. 400 — неверные параметры/образ; 401 — нужен логин; 403 — нет токена; 409 — конфликт состояния; 503 — нет подтверждения/очередь недоступна; 507 — ошибка записи настроек. Успех POST означает подтверждение климатического ядра, а не только помещение команды в очередь. При тайм-ауте команда могла быть обработана позднее: перечитайте статус перед повтором.
